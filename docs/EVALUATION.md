# 模型与体验评测

## 不把“接口成功”当“用户认可”

分别看内容理解、角色表达、行动选择、实际交付与播放体验。一个 HTTP 成功结果仍可能唱半句、选错配乐或在错误话题下投递。

## 已做的真实迭代（质性结果）

- 聊天候选通过匿名 A/B/C 内容比较与连续对话测试，由负责人评价自然度、共情、延伸话题和文学性；最终结合成本采用 Flash 聊天方案。没有足够样本得出通用模型排名。
- 音频理解用原作的明确时间点、器乐进入和情绪变化核对；把用户纠正与模型推断分开，避免把歌词分析当作已听懂编曲。
- 跟唱对比说话音色与唱歌听感，调整音高策略，记录漏尾句、半句、滑音台阶与偶发破音；个别轻微瑕疵在 MVP 可接受，但整句完整度是硬要求。
- Mlog 以真实日常与排练视频核对画面含义、配乐强弱、时长和转折。自动产物、人工调整与演示样品必须区分。

## 回归方式

把已发现的失败分配到意图、上下文、任务、投递或媒体处理层，再建立最小反例。使用隔离数据，保留失败而不只存最终成功截图。公开仓库仅测试独立规则示例，不包含这些私人歌曲与聊天夹具。

## 当前证据限度

核心体验的认可主要来自负责人；部分真实云 API 混合测试完成，但不等于十人完整产品试用，更不证明生产 GPU 跟唱。无外部留存、满意度、转化率统计。性能与成本随供应商、内容长度和缓存变化，未在此给出无条件承诺。
