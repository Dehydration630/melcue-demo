# MelCue：从宣发工具，到一个愿意听你作品的人

## 起点

音乐人完成作品后，需要做发行、内容、粉丝运营。最初的 StageCue 试图覆盖这条链路，但渠道接口和行业资源限制让“一键全流程”很难兑现。更重要的是，作品是否愿意持续被分享，不仅取决于生成了几条文案。

## 我怎样收窄问题

创始人同时是音乐创作者，使用自己的歌曲与排练素材反复体验。抽象歌曲配具象 AI 视频不符合表达；相比之下，真实生活与排练素材的粗剪更有启发。另一轮短句跟唱测试中，“有人在唱我写的歌”的感受明显成立，于是产品转向 AI 乐迷陪伴，让工具在交流中自然出现。

这些是深度个案证据，不是已完成的市场验证。下一步需通过外部音乐人的真实使用检验可迁移性。

## 设计的三个闭环

1. **被理解 → 被回应**：从整体听感到具体歌词，满足条件后自然跟唱完整一句。
2. **有灵感 → 留下来**：一次给出一句歌词；得到明确认可，再保存到歌词本。
3. **分享生活 → 获得启发**：先交流素材，发现可行方向后邀约；用户接受，再交付 Mlog 粗剪。

## 从失败中得到的产品约束

“答应了没做”暴露出对话与执行不一致；“回复重复”暴露出旧计划或结果归属不清；“画面安静但配乐最猛烈”暴露出仅靠标签挑音乐的问题。修复方向是明确状态与证据，而不是为某首歌不断添加特判。

## 当前交付与限制

核心场景完成本机体验迭代，部分云链路已真实验证。云端完整跟唱、音色转换用途许可及正式运行条件仍未齐备；不将其描述成已上线产品。没有外部用户增长、留存或付费数据。

我的贡献集中在定位、体验标准、模型对比、反例验收与交付边界；实现由 AI 编程工具协作完成。仓库中的交互是重新制作的可公开示意，不是产品录屏，也不证明模型效果。
