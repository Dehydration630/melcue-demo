# MVP 产品需求摘要

## 目标

让音乐人感到作品被认真在意，并愿意再次带来作品、日常或创作问题。是否形成持续关系，需外部试用验证。

## 场景与边界

| 场景 | 行为 | 不做什么 |
|---|---|---|
| 日常交流与陪伴 | 根据交流意图选择简短回应或独立观点，积累待聊线索 | 不复述上一轮凑回应，不伪装真人 |
| 作品交流 | 整体听感、歌词、灵感、受众；自然完整短句跟唱 | 不凭单个“唱”字切场景，不把猜测当作者事实 |
| 素材交流 | 感受优先、少罗列物品；视频满足条件时邀约 Mlog | 照片不自动邀约成片，不未经接受就制作 |
| 共同创作 | 一次一句、主动给出具体歌词、认可后存歌词本 | 不输出整篇歌词，不生成新音乐 |
| 音乐交流与推荐 | 围绕具体特点找歌，简短自然地说理由 | 不默认用户没听过熟歌，不把主观关联当客观等同 |
| 运营推广这首歌 | 作品页按钮进入的保留入口 | MVP 不深化投放、发行或行业资源执行 |

## 跨场景规则

- 交流目标、当前作品及版本、后台任务、待聊话题分别记录。
- 跟唱使用原歌已定位的完整演唱单元；重复出现而未指明时默认第一遍。不是按用户引用字数机械截断。
- 首次交流优先让用户体验可跟唱句；准备慢时先聊听感，完成后自然补上，不用虚假的就绪承诺。
- Mlog 可含多个画面素材，只用一个连续音乐片段；默认配音乐，状态反差须画面与音乐同时成立且节点同步。
- 所有后台等待显示对话间状态小字；操作取消、删除、换对象后校验结果归属。
- 每天主动开场需用户开启；当地时间 22 点检查，当天用户已主动聊过则不再打扰。
- 点赞、点踩可追溯对应输出；删除聊天同步处理关联上下文与派生记忆，不将删除内容重新注入。

## 首批验收

外部试用尚未开始。关注能否完成首次“被理解＋自然跟唱”、下次是否自发带来内容，以及等待、重复、错误归属是否破坏体验。技术成功不替代听感验收。
