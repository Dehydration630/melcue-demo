# 关键决策与反例

| 反例或约束 | 决策 | 权衡 |
|---|---|---|
| 完整宣发链路依赖渠道权限和真实资源 | 从音乐人的持续交流切入 | 缩小商业化叙事，换取可验证体验 |
| 炫目生成视频不一定符合原作 | 保留真实素材，Mlog 只交启发性粗剪 | 不承诺直接可发布或流量 |
| 固定两条、固定短句都显得机械 | 按回应动作调整条数和篇幅 | 不以统一字数替代理解 |
| 只有引用的半句被唱出来 | 匹配完整演唱单元后再截音频 | 定位质量仍可能限制覆盖率 |
| 准备未完就答应、旧结果重新出现 | 对话、任务、版本、投递分别管理 | 增加显式状态，但降低隐含竞态 |
| 歌词反复问方向却不产出 | 适时主动给一句，认可后记录 | 不越界一次写完整首 |
| 音乐反差与画面转折错位 | 同一连续音乐片段，双侧反差且同步 | 不满足时不强行邀约 |
| 小模型更便宜但部分表达较弱 | 结合真实任务选型，聊天采用 Flash 方案 | 无条件宣称模型等效不成立 |

## 没有采用的方向

暂不实现复杂剪辑器、全链路自动发行、即兴生成音乐、整首歌词组合与成熟运营代理。AI 角色不偷偷替换为真人；运营角色扩展仅为后续探索。
